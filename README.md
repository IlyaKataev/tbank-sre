# Маркетплейс

Клиент-серверное приложение для управления товарами, заказами и промокодами: веб-интерфейс, REST API на Go и PostgreSQL. Фронтенд встроен в бинарник и работает на одном адресе с API. Для запуска нужны два постоянных контейнера: приложение и база данных; миграции выполняются отдельным одноразовым процессом.

## Быстрый старт

Требования: Docker Engine, Docker Compose **2.24.4+**, Make и Python 3. Go и Node.js на хосте для запуска не нужны.

```bash
make env       # создаёт .env со случайными локальными секретами; существующий файл не меняет
make build     # собирает готовый образ tbank-sre:local
make up        # запускает PostgreSQL, миграции и приложение; ждёт readiness
```

Открыть <http://localhost:8080>. При регистрации доступны роли продавца (`SELLER`) и покупателя (`USER`). Создайте аккаунт **продавца**, добавьте товар, отредактируйте его и отправьте в архив. Продавец изменяет только свои товары. Аккаунт покупателя позволяет просматривать каталог.

`DELETE /products/{id}` выполняет **мягкое удаление**: ставит `ARCHIVED`. Товар исчезает из активного каталога, но остаётся в БД и доступен через фильтр архива. Это сохраняет историю заказов.

```bash
make logs      # JSON-логи приложения
make down      # останавливает стенд, сохраняя том PostgreSQL
make up        # данные и аккаунты сохраняются
```

Не удаляйте том БД, если нужно сохранить данные. Изменение `POSTGRES_PASSWORD` в существующем `.env` требует соответствующего изменения пароля в PostgreSQL. Порт приложения по умолчанию доступен только на loopback хоста.

## Сборка, релиз и запуск

`make build` собирает код и встроенный фронтенд. Приложение запускается из готового образа; миграции выполняются отдельной командой.

Для именованного релиза задайте версию:

```bash
VERSION=1.0.0
make build VERSION="$VERSION"
make up VERSION="$VERSION"
```

Образ получает OCI-метки `version` и `revision`. Во всех окружениях используется один и тот же готовый образ; различается конфигурация. Для отката приложения передайте в `make up VERSION=...` версию сохранённого предыдущего образа, совместимого с текущей схемой БД.

Миграции включены в тот же образ и используют ту же конфигурацию:

```bash
make migrate VERSION="$VERSION"
```

Compose также запускает мигратор перед стартом приложения. Повторное применение уже выполненных миграций безопасно.

## Конфигурация

`.env` игнорируется Git и исключён из Docker build context и архива. Образ не содержит секретов. `.env.example` содержит только имена и несекретные настройки.

| Переменная | Назначение / значение по умолчанию |
|---|---|
| `POSTGRES_PASSWORD` | Пароль БД для локального Compose; `make env` генерирует случайное значение |
| `DB_DSN` | Обязательный DSN для бинарника; Compose формирует его из настроек БД |
| `JWT_SECRET` | Обязательный ключ подписи, минимум 32 байта |
| `HTTP_PORT` | Порт бинарника, `8080`; в Compose фиксирован внутри контейнера |
| `APP_PORT` | Порт на хосте для Compose, `8080` |
| `JWT_ACCESS_TTL` / `JWT_REFRESH_TTL` | `15m` / `168h` |
| `ORDER_RATE_LIMIT_MINUTES` | Интервал операций с заказами, `1`; `0` отключает ограничение |
| `LOG_LEVEL` | `info` |
| `DB_CONNECT_TIMEOUT` | Таймаут начального подключения, `10s` |
| `READY_TIMEOUT` | Таймаут проверки БД, `2s` |
| `SHUTDOWN_TIMEOUT` | Время завершения активных HTTP-запросов, `10s` |

Некорректные обязательные настройки, длительности, уровень логов и порт приводят к завершению с ошибкой до запуска HTTP-сервера. Для внешней БД передайте её DSN, включая необходимые TLS-параметры; менять код не требуется.

## Проверки здоровья и масштабирование

- `GET /healthz` — жив ли процесс, без обращения к БД.
- `GET /readyz` — доступна ли БД; при ошибке или завершении процесса возвращает `503`.
- `SIGTERM` — прекращение приёма запросов и graceful shutdown; Compose даёт процессу 15 секунд.

Две реплики приложения за Nginx:

```bash
make scale
python3 scripts/smoke.py --base-url http://127.0.0.1:8080
```

В этой конфигурации только прокси публикует порт хоста. Обе реплики используют общие PostgreSQL и JWT-ключ; Nginx обновляет адреса реплик через Docker DNS.

Остановка конфигурации с прокси с сохранением данных:

```bash
docker compose -f docker-compose.yml -f docker-compose.scale.yml down
make up
```

## Проверки

```bash
make test      # модульные тесты
make test-e2e  # HTTP-сценарии с PostgreSQL в Testcontainers
make smoke     # HTTP-проверки запущенного стенда
```

`make test-e2e` использует Docker socket и host network Linux. Он запускает отдельную тестовую БД, не подключается к данным рабочего Compose. На Docker Desktop E2E можно запускать с локальным Go после `make generate`: `go test ./internal/e2e/... -v -count=1 -timeout 3m`.

## Разработка и API

Стек: Go 1.26, chi, pgx, sqlc, oapi-codegen, golang-migrate, zerolog; PostgreSQL 18; HTML/CSS/JavaScript без внешних UI-зависимостей.

- `web/` — интерфейс и `go:embed`.
- `cmd/server/`, `internal/` — HTTP, бизнес-логика и доступ к БД.
- `cmd/migrate/`, `internal/migrations/` — одноразовая команда и SQL-миграции.
- [api/openapi.yaml](api/openapi.yaml) — контракт API; `/healthz` и `/readyz` реализованы отдельно.
- `scripts/smoke.py` — проверка запущенного приложения.
- [Отчёт.md](Отчёт.md) — доменная область, сущности и все 12 факторов.

Сущности: пользователи, товары, заказы с позициями, промокоды. Интерфейс покрывает управление товарами; операции заказов и промокодов доступны через API.

| Группа | Методы |
|---|---|
| Авторизация | `POST /auth/register`, `/auth/login`, `/auth/refresh` |
| Товары | `GET/POST /products`, `GET/PUT/DELETE /products/{id}` |
| Заказы | `POST /orders`, `GET/PUT /orders/{id}`, `POST /orders/{id}/cancel` |
| Промокоды | `POST /promo-codes` |

Для локальной разработки нужен Go 1.26.1+: `make generate` ставит закреплённые генераторы в `bin/tools` и генерирует Go-код из OpenAPI/SQL, `make local-build` собирает оба бинарника. Генерируемый код исключён из Git; Docker воспроизводит его при каждой сборке исходников.

## Архив исходников

Команда выполняется из рабочей копии Git и архивирует текущий коммит. Перед упаковкой сохраните нужные изменения коммитом:

```bash
make archive
```

Результат: `dist/tbank-sre.zip`, исходники и `Отчёт.md` из текущего коммита без `.git`, `.env`, бинарников и тестовых данных.
